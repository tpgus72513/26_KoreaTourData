> 이 문서는 최초 검토와 로컬 수정 시점의 기록이다. 후속 요청으로 [논문 기반 계산 기능](../research/scoring-implementation.md)을 추가하고 검증 후 push하는 범위까지 승인받았다. 아래의 ‘push하지 않음’, ‘계산모형 후속 구현’은 최초 작업 당시 상태이며 최신 구현은 링크 문서를 따른다.

- 대상: `tpgus72513/26_KoreaTourData`

## 1. 판단

**지도 → 권역 비교 → 근거 → 과제 → 현장검증 → 보고서의 구조는 유지할 가치가 있다.** Next.js·TypeScript·PostgreSQL/PostGIS의 현재 구성도 MVP를 진행하기에 충분하다. 지금 필요한 개선은 데이터가 부족하거나 저장에 실패했을 때도 화면이 사실에 맞게 동작하도록 만드는 것이다.

공모전에서 설명할 차별점은 화면 수보다 **한 판단의 출처·계산·한계·현장 확인·후속 과제를 연결하는 능력**이다. 현재 레포는 업무 시연의 출발점이며, 과학적으로 검증된 관광권역 평가모형까지 완성한 상태는 아니다.

| 유지할 부분 | 이유 |
|---|---|
| 데모와 라이브 모드의 분리 | 실측과 시연값이 섞이는 것을 방지 |
| 안동시 방문자와 작은 권역의 분리 | 행정구역 통계를 세부 권역 성과로 오인하지 않음 |
| 권역 점수의 산출 보류 | 독립 자료가 없는 경우 숫자를 만들지 않는 방향이 적절 |
| PostgreSQL/PostGIS·동기화 스냅샷 | 공간 조회와 마지막 정상 발행본 관리에 적합 |
| 공개 조회와 관리자 저장의 분리 | 현장업무 기록의 접근 범위를 구분 |
| 기존 69개 테스트 | 기본 동작을 확인할 기반. 이번에 발견한 경계 사례를 추가해야 함 |

## 3. 점수 근거에 관한 결정

이번에는 검증되지 않은 계산을 추가하지 않는다. 기존 초기 가중치와 근거 없는 신뢰도 수치는 평가 근거로 사용하지 않는다. 세부 지표 입력이 없으면 비교·상세 화면에서 동일하게 보류한다. 데모 총점은 명시적인 화면 예시로만 남긴다.

실제 평가기능을 완성하는 순서는 [평가·근거 표시 계약](../evaluation-policy.md)에 정의했다. 논문은 항목 선정과 방법론의 근거이며, 우리 지역의 가중치·점수·사업효과를 자동으로 검증해주지 않는다.

**F01~F16에 대한 코드 수정과 회귀 검증을 완료했다.** Node.js 24.11.0 / npm 11.6.1 / Windows 환경에서 확인했으며, 관리자 비밀과 DB 연결 없이 데모 모드로 브라우저를 검증했다.

### 확인하지 않은 범위와 남은 한계

- **실 API·Supabase DB**: 테스트는 모의 응답과 데모로 수행했다. 기존 README에 기록된 과거 probe와 이번 수정의 실연동 검증을 혼동하지 않는다. 실제 키의 승인·할당량·응답 및 DB 트랜잭션은 테스트 환경에서 추가 확인해야 한다.
- **GitHub Actions**: 설정 파일을 추가했지만 push하지 않았으므로 GitHub에서 실행한 결과는 없다.
- **평가모형**: 검증된 가중치, 실제 권역별 지표와 평가 이력은 아직 없다. 이번 변경은 근거 없는 숫자를 제거하고 한계를 일관되게 표시하는 작업이다.
- **배치 시간 제한**: 외부 요청은 응답 본문까지 10초, 수집 배치는 35초로 제한했다. DB 작업은 이 수집 제한 바깥이므로 배포 환경의 DB 지연·함수 종료도 별도로 검증해야 한다.
- **변동하는 원천 목록**: 페이지를 읽는 동안 총계나 목록이 바뀌면 보수적으로 발행을 중단하고 마지막 정상본을 유지한다. 운영 중 반복된다면 수집 창·재시도 정책을 조정한다.
- **실사용 검증**: 현장 관계자·관광약자 당사자의 사용성 평가와 실제 사업 성과 검증은 수행하지 않았다.

### 코드 인수 방법

수정본은 로컬 `codex/review-and-improvements` 브랜치의 미커밋 변경사항이다. **commit·push·PR 생성·배포를 하지 않았다.** 기존 DB 마이그레이션과 패키지 잠금 파일은 유지했다.

별도 제공하는 ZIP에는 변경된 소스, 테스트, 문서, CI 설정과 기존 프로젝트 파일을 함께 넣는다. `.git`, `node_modules`, `.next`, 실제 환경변수 파일은 포함하지 않는다. ZIP을 사용할 경우 압축을 풀고 Node.js 24에서 `npm.cmd ci`, `npm.cmd run dev`를 실행하면 데모를 확인할 수 있다. 비밀 없이 구조를 설명하는 `.env.example`만 포함한다.

## 6. 시연 구성 제안

1. 지도에서 권역을 선택하고 ‘선택’과 ‘추천’이 다른 상태임을 보여준다.
2. 비교·상세에서 점수 산출 보류, 자료 기간, 출처와 논문 기반 평가 절차를 확인한다.
3. 현장검증 과제를 생성하고 담당자·질문·메모를 기록한다.
4. 수정 내용을 실행과제와 보고서에서 다시 확인한다.
5. 보고서에서 예시/라이브, 오래된 자료, 확인하지 못한 사항을 함께 설명한다.

‘개발하면 관광소비가 몇 % 증가한다’는 예측 대신, **‘어떤 근거가 부족하고 무엇을 확인해야 사업 검토가 가능해지는가’**를 보여주는 것이 현재 구현에 맞는 설명이다.
