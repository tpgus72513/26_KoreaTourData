# 동행로컬 — 논문 근거와 점수 계산 설계안

작성일: 2026-09-18 · 상태: **문헌에 기반한 설계 제안 / 전문가 조사·실증 검증 전**

## 1. 제안하는 결론

**문헌으로 평가항목을 정하고 → 지역 이해관계자가 가중치를 검토하고 → 동일한 기준으로 계산하고 → 현장과 민감도 분석으로 검증한다.**

동행로컬에는 **델파이 방식의 지표 검토 + AHP 가중치 + 0~100점 가중합 + 필수조건 별도 확인**을 권한다. 후보 권역 3곳을 비교하는 MVP에서 계산 과정을 설명하고 구현하기에 적합하다는 설계 판단이다.

기존에 제안한 **30·25·20·15·10%는 논문에서 검증된 비율이 아니다.** 확정 가중치로 사용하지 않는다. 아래의 5영역과 구체적 지표·산식도 여러 연구를 참고해 우리 목적에 맞게 구성한 제안이며, 특정 논문의 검증된 척도를 그대로 복제한 것이 아니다.

| 사용자가 알고 싶은 것 | 서비스가 보여줄 것 | 해석 범위 |
|---|---|---|
| 관광을 운영할 기반이 있는가? | **관광권역 여건 점수**, 영역별 강점·부족 | 현재 기반과 이용 조건 |
| 방문·체류·지역소비가 실제로 어떤가? | **관광 성과판** | 확보된 기간·공간단위에서 관측한 성과 |
| 무엇부터 실행해야 하는가? | **사업 검토 의견**, 근거, 선행 조사, 실행조건 | 현장·비용·운영주체를 고려한 검토 |
| 이 판단을 얼마나 확인했는가? | **자료 확보율**, 조사 범위, 출처·기준일 | 자료 확보와 검증 상태 |

**여건 점수는 미래 성장확률이나 사업 투자효과가 아니다.** 낮은 체류·소비는 문제 발견의 근거일 수 있지만, 사업을 하면 크게 개선된다는 증거까지 되지는 않는다.

| 관광자원·지원 여건·사회·환경 등을 함께 볼 필요 | 5개 영역의 최종 구성과 명칭 |

**논문 수가 많다고 우리 점수의 타당성이 자동으로 확보되지는 않는다.** 지표의 정의, 실제 데이터, 지역 검토, 재현 가능한 계산이 함께 있어야 한다.

## 3. 평가영역과 지표 후보

다음은 **서비스용 지표 후보**다. 영역당 1–3개를 선정하는 것을 MVP 목표로 삼되, 중요한 개념을 빼면서 개수를 맞추지는 않는다. 방문량·검색량·실제 소비는 별도 성과판에서 다루어 현재 인기와 관광 여건이 중복 반영되지 않게 한다.

| 영역 | 답할 질문 | 측정 후보와 계산 방향 | 필요한 자료 | 문헌 연결 |
|---|---|---|---|---|
| **A. 관광자원 기반** | 제안한 관광 테마를 운영할 자원이 있는가? | 테마에 필요한 자원 유형 충족 정도, 선정한 핵심 자원의 운영 가능률 | 관광자원 분류·위치·상세정보 + 운영자 확인 | R1·R2 |
| **B. 체류·지역소비 지원 여건** | 관광객이 머무르고 지역 사업체를 이용할 조건이 있는가? | 운영 중인 숙박·식음 자원과 연결되는 핵심 관광지 비율, 참여·운영이 확인된 지역 사업체 연결 여부 | 관광정보 + 경로/운영시간 + 사업체 확인 | R2·R5 |
| **C. 권역 내 이동 연결** | 주요 관광지와 교통 거점을 연결할 수 있는가? | 사전 지정한 주요 지점 쌍의 이동시간, 계획 시간 내 연결되는 지점 쌍 비율 | 도로·교통 경로자료, 시간표, 현장 확인 | R2 |
| **D. 관광약자 이용 여건** | 지정한 이용자가 실제 동선과 서비스를 이용할 수 있는가? | 이용자 유형별 필수 동선 충족 상태, 검증된 안내·예약·현장지원 조건 | 무장애 관광정보 + 당사자·전문가 현장 확인 | R4·R9 |
| **E. 주민·환경 여건** | 주민 생활과 환경 부담을 고려해 운영할 수 있는가? | 주민 의견 조사, 관리주체가 정한 환경·혼잡 기준의 충족 상태 | 주민조사, 관리기관 자료, 현장 관측 | R3·R6 |

세부 정의 시 지킬 사항:

- **자원 유형이 다양할수록 무조건 좋다고 하지 않는다.** 생태 특화 권역과 도심 복합 권역의 목적이 다르므로 테마와 비교집단을 먼저 정한다.
- **시설 개수만으로 점수를 올리지 않는다.** 면적이 넓은 권역이 유리해지고 운영·이동 가능성을 놓친다. 가능하면 핵심 관광지와의 기능적 연결을 측정한다.
- **주민 몇 명의 의견을 지역 전체 수용성으로 표시하지 않는다.** 조사대상·모집 방식·응답 수와 한계를 함께 남긴다.
- **환경·주민 자료가 없으면 E영역은 미완성이다.** 관광정보 API만으로 지속가능성 전체를 측정했다고 발표하지 않는다.
- 혼잡·방문량·공급량·체류일수는 항상 ‘많을수록 좋다’고 보기 어렵다. 목적에 맞는 방향·목표범위를 검토한다.

### 공공데이터로 가능한 부분

[한국관광공사 국문 관광정보 서비스](https://www.data.go.kr/data/15101578/openapi.do)는 관광자원·위치·분류·숙박·상세정보 등 기초자료의 출처다. [무장애 여행정보 서비스](https://www.data.go.kr/data/15101897/openapi.do)는 접근성 조사 대상과 제공 정보를 확인할 후보 출처다. 실제 사용할 필드·누락률·갱신일은 활용신청 후 응답 표본과 명세로 검증해야 한다.

| 자료 | 가능한 활용 | 해당 자료만으로 확정할 수 없는 것 |
|---|---|---|
| 관광자원·숙박·음식점 위치/분류 | 자원 목록, 공간 분포, 근접성 | 현재 영업, 실제 체류, 지역 매출 |
| 무장애 안내정보 | 제공된 조건과 미확인 항목 파악 | 모든 이동구간의 현재 이용 가능성 |
| 내비게이션·연관 관광지 자료를 확보한 경우 | 해당 서비스 이용 기준의 이동·관심 신호 | 실제 관광객 인원, 도보·휠체어 동선 |
| 시군구 단위 관광 성과자료를 확보한 경우 | 해당 행정구역의 성과와 배경 | 그 안의 작은 관광권역 각각의 실측 성과 |
| 별도 현장·주민·사업체 조사 | 운영·참여·이용조건 확인 | 조사 밖 장소·집단 전체의 상태 |

본 문서는 API 인증키로 실제 데이터를 호출·분석한 결과가 아니다. 특히 관광 성과자료의 세부 공간단위·이용권한·비식별 처리에 따른 제공 범위는 확보 후 확인한다.

## 4. 계산 순서

### 4-1. 먼저 비교 기준을 고정한다

권역 경계, 관광 테마, 핵심 관광지 목록, 평가기간, 교통수단, 이용자 유형을 정한다. 이 기준을 점수가 잘 나오도록 사후 변경하지 않는다.

예를 들어 휠체어 이용자를 위한 동선을 평가했다면 화면에도 **‘휠체어 이용자 기준 / 지정 동선 3개 대상’**이라고 표시한다. 이를 관광약자 전체에 대한 판정으로 확대하지 않는다.

각 지표는 아래 정보를 가져야 한다.

| 필수 기록 | 예시/설명 |
|---|---|
| 무엇을 측정하는가 | 핵심 관광지에서 운영 중인 숙박시설까지의 연결 |
| 원자료와 단위 | 분, 개, 비율, 상태 등 |
| 분모·대상 | 고정한 관광지 목록, 동선 목록, 응답자 집단 |
| 공간·시간 범위 | 권역 경계, 조사월, 운영시간대 |
| 근거 출처 | API/원자료 주소, 수집일, 조사 기록 |
| 측정 유형 | 직접 관측 / 여건 대리지표 / 추정 / 미확인 |
| 점수 기준 | 좋은 방향, 0점·100점 기준, 기준의 선정 이유 |
| 문헌 연결 | 해당 개념을 채택한 연구와 서비스용 수정 내용 |
| 계산 버전 | 지표·가중치·정규화·자료 버전 |

### 4-2. 서로 다른 단위를 0~100점으로 변환한다

높을수록 좋은 지표:

`z = 100 × clip((x − L) / (U − L), 0, 1)`

낮을수록 좋은 지표:

`z = 100 × clip((U − x) / (U − L), 0, 1)`

- `x`: 측정값, `L/U`: 사전에 정한 하한/상한, `clip`: 0 미만은 0, 1 초과는 1로 제한.
- 기준은 적용 가능한 관리 목표, 전문가 검토를 거친 평가 기준, 충분한 비교집단의 고정 기준 등에서 정한다.
- **후보 3곳만 놓고 최솟값=0점, 최댓값=100점으로 만들지 않는다.** 작은 차이가 과장되고 비교대상 추가만으로 점수가 변할 수 있다.
- 비율 지표는 목적상 적절하면 비율 자체를 0~100점으로 사용할 수 있다. 범주·등급을 임의로 등간격 숫자로 변환하지 않는다.
- `L=U`이거나 방향·기준의 근거가 없으면 그 지표의 점수 산출을 보류한다.

**계산 예시 — 아래 숫자는 설명을 위한 가상 기준이다.**

‘핵심 관광지의 숙박 연결률’이 70%이고, 검토를 거쳐 20%를 0점·100%를 100점으로 정했다고 가정하면:

`100 × (70 − 20) / (100 − 20) = 62.5점`

이 예시는 계산법을 보여준다. **20%가 논문에서 검증된 기준이거나 실제 숙박·매출 증가를 예측한다는 뜻은 아니다.**

### 4-3. 가중치는 AHP 조사로 정한다

R1·R7을 참고해 다음 절차를 권한다.

1. 문헌에서 뽑은 지표를 지역 관광 실무자·운영자·주민·접근성 당사자/전문가가 검토한다. 중복·측정 불가·정책 부적합 항목을 수정한다.
2. 델파이 방식으로 익명 의견과 수정안을 다시 제시한다. MVP는 2회 검토부터 계획할 수 있으나, 이는 일정 제안이며 R1의 3회 절차를 그대로 재현한 것은 아니다.
3. 확정한 영역과 점수 기준을 보여주고 AHP 쌍대비교를 받는다. 상위 5영역은 1인당 `5×4÷2 = 10개` 비교다.
4. 표준 AHP의 1–9 비교척도로 역수행렬을 만들고 우선순위 벡터를 계산한다. 복수 응답을 통합할 경우 응답 행렬의 기하평균 등 선택한 집단 의사결정 방식을 명시한다.
5. 응답별 일관성과 집단의 의견 차이를 점검한다. 단순히 원하는 순위를 얻기 위해 응답자를 빼거나 가중치를 조정하지 않는다.

조사 규모는 역할을 균형 있게 포함하는 **8–12명 내외를 초기 모집 목표**로 제안한다. 이는 팀 일정상 제안이지, 학술적으로 충분한 표본 수가 보장된다는 뜻은 아니다. 전문가 모집이 안 되면 조사했다고 쓰지 말고 임시 모형으로 표시한다.

가중합의 가중치는 서로 다른 조건 사이의 교환관계를 담는다. 따라서 ‘접근성이 얼마나 중요한가’만 묻지 말고 **각 영역이 무엇이며 0점에서 100점으로 바뀌는 것이 어떤 변화인지**도 설명해야 한다.

기술식:

`A w = λmax w`, `Σw = 1`

`CI = (λmax − n) / (n − 1)`

`CR = CI / RIₙ`

통상 약 0.10 이하를 일관성 검토에 활용한다. 이 수치의 공개 원문 근거는 [Wind & Saaty (1980), p.646](https://faculty.wharton.upenn.edu/wp-content/uploads/2012/04/8002_Marketing_Applications_of_the_Analytic.pdf)에 있다. 구현할 때 행렬 크기에 맞는 RI 표의 출처·버전을 고정한다. **CR은 판단 일관성을 검사하며 예측 정확도나 정책 타당성을 보증하지 않는다.**

하위 지표가 2개면 2×2 역수행렬은 항상 일관적이고 RI가 0이므로 CR을 계산하지 않는다. 이 경우 ‘해당 없음’으로 기록한다.

### 4-4. 영역별 점수와 종합점수를 계산한다

`영역점수 Dᵢₖ = Σⱼ vₖⱼ × zᵢₖⱼ`

`권역점수 Sᵢ = Σₖ wₖ × Dᵢₖ`

- `wₖ`: 영역 가중치, 전체 합 1.
- `vₖⱼ`: 해당 영역 안의 지표 가중치, 영역별 합 1.
- 모든 지표 점수 `z`는 0~100.
- 영역 안에 지표가 많다는 이유만으로 그 영역의 비중이 커지지 않게 먼저 영역별로 계산한다.
- 화면에는 점수뿐 아니라 `영역점수 × 가중치 = 총점 기여분`을 보여준다.

**가상 예시 — 모든 값은 설명용이며 실제 권역 평가가 아니다. 가중치 20%는 전문가 조사 전의 임시 시연 기준이다.**

| 영역 | 점수 | 임시 가중치 | 총점 기여분 |
|---|---:|---:|---:|
| 관광자원 기반 | 80 | 20% | 16 |
| 체류·지역소비 지원 여건 | 60 | 20% | 12 |
| 권역 내 이동 연결 | 70 | 20% | 14 |
| 관광약자 이용 여건 | 50 | 20% | 10 |
| 주민·환경 여건 | 65 | 20% | 13 |
| **합계** | | **100%** | **65점** |

동등가중치도 가치판단이다. 최종 화면에서 ‘논문으로 검증된 비율’이라고 표시하지 않는다.

### 4-5. 미확인 값은 0점으로 넣지 않는다

확인 결과 미충족인 것과 확인하지 못한 것은 다르다. 권역마다 빠진 지표의 가중치를 나머지에 재배분하면 서로 다른 기준으로 비교하게 된다.

초기 서비스는 핵심자료가 빠지면 **확정 총점·순위를 보류**하고 확인된 지표와 조사할 항목을 보여준다. 필요하면 계산상 가능한 범위를 표시한다.

`하한 = Σ(확인된 지표의 전역 가중치 × 점수)`

`상한 = 하한 + 100 × Σ(미확인 지표의 전역 가중치)`

`평가자료 확보율 = 100 × Σ(사용 가능한 지표의 전역 가중치)`

전역 가중치는 `영역 가중치 × 영역 내 지표 가중치`다. ‘사용 가능’은 값·출처·시점·공간단위가 사전 분석 기준에 맞는 경우를 뜻한다.

위 예시에서 접근성 점수 50을 알 수 없다면:

- 확인된 기여분: `16 + 12 + 14 + 13 = 55`
- 미확인 가중치: `0.20`
- **가능범위: 55~75점 / 평가자료 확보율 80% / 접근성 현장확인 필요**

55점이 확정 점수인 것도, 55~75가 통계적 신뢰구간인 것도 아니다. 확보율 80% 역시 모델 정확도나 사업 성공확률이 아니다.

접근성에서는 자료 확보율 외에 **대상 동선 3개 중 몇 개를 조사했는지**도 별도로 보여준다. 일부만 확인하고 전체를 확인한 것처럼 100점을 줄 수 없다. 최신성·공간 일치·관측/추정·현장 확인 상태도 별도 표시한다.

### 4-6. 필수 이용조건은 총점과 별도로 확인한다

가중합에서는 높은 자원 점수가 심각한 이용 장벽을 숫자상 상쇄할 수 있다. 따라서 아래는 합산과 별도로 표시하는 **서비스 운영 규칙**으로 둔다.

| 확인 결과 | 제안할 처리 |
|---|---|
| 지정 이용자의 필수 동선이 끊김 | 해당 코스는 수정 또는 장벽 개선을 먼저 검토 |
| 필수 동선의 상태를 모름 | 현장조사를 먼저 제안 |
| 사업 구상과 환경 관리조건이 충돌 | 규모·동선·운영방식을 조정한 뒤 검토 |
| 운영 주체·관리주체 참여가 미확인 | 실행 가능성 조사부터 시작 |

이는 R4·R8·R9의 논의를 참고한 자체 규칙이며, 논문에 실린 동일한 판정모형은 아니다. 접근성이 낮은 지역을 투자 대상에서 제외한다는 뜻도 아니다. **장벽 개선 자체가 우선 사업이 될 수 있다.**

## 5. 점수를 사업 추천으로 연결하는 방법

**현재 조건이 좋다는 것과 개선사업을 우선 시행할 가치가 있다는 것은 다른 판단이다.** R6은 지표를 계획에 연결하는 근거로 사용하되, 아래 규칙은 MVP용으로 단순화한 우리 제안이다.

0~100점으로 정규화한 영역에서 목표와의 차이를 계산한다.

`개선 필요 격차 Gᵢₖ = max(0, 사전 목표점수 Tₖ − 현재 영역점수 Dᵢₖ)`

목표점수도 전문가·지역 실무자가 이유를 정하고 공개한다. 격차가 크다고 개선효과가 크다고 단정하지 않는다.

| 발견한 조건 | 추가로 확인할 것 | 사업 검토 의견 예시 |
|---|---|---|
| 자원은 있으나 숙박·식음 연계가 약함 | 실제 이용 수요, 이동 장벽, 영업시간, 사업체 참여 | 운영 가능한 체류·상권 연계 코스의 소규모 실증 |
| 핵심 동선의 이용 장벽이 확인됨 | 이용자 요구, 개선 방법·비용, 관리 권한 | 해당 동선의 접근성 개선부터 검토 |
| 시설은 가까우나 이동·운영 연결이 불명확함 | 실측 경로, 시간표, 운영일 | 코스 설계 전 이동·운영 조사 |
| 자료가 부족해 결론이 달라질 수 있음 | 누락 핵심자료, 현장 검증 | 개발사업 제안보다 조사과제 우선 |
| 혼잡·주민 부담이 확인됨 | 운영시간·공간 분산, 주민 의견 | 수요 확대보다 부담을 줄이는 운영 개선 |

사업별 카드에는 **발견 근거 → 개선 가설 → 선행조건 → 담당 주체 → 비용/기간의 확인 상태 → 검증할 성과지표**를 남긴다. AI는 확인된 근거를 설명하고 문서를 작성하는 역할로 제한하며, 가중치나 효과 수치를 임의 생성하지 않는다.

## 6. 점수의 타당성을 검증하는 계획

| 검증 | 실제로 할 일 | 남길 증거 |
|---|---|---|
| 내용 타당성 | 지표가 지역 문제를 포괄하는지 실무자·주민·접근성 당사자가 검토 | 지표 채택/삭제 이유, 수정 이력 |
| 가중치 타당성 | 정의·점수 범위를 제시한 AHP 조사, 일관성과 관점 차이 확인 | 익명 응답, 역할 구성, 가중치, CR 적용 여부 |
| 데이터 적합성 | 같은 기간·단위·모집단인지 확인, API 표본과 현장 사실 대조 | 원자료, 수집일, 누락률, 현장 확인 기록 |
| 순위 안정성 | AHP와 동등가중치 비교, 일부 가중치의 상대 ±20% 변경 후 재정규화 등 | 점수·순위·추천의 변동표 |
| 측정 재현성 | 같은 조사기준으로 다른 조사자가 다시 판정 | 항목별 불일치와 해결 기록 |
| 외부 검토 | 가중치 설계에 참여하지 않은 실무자에게 근거와 결론을 검토받음 | 동의·반론·추천 변경사항 |
| 후속 성과 | 실증 전후의 체류·지역소비·이용장벽 변화를 적합한 단위로 관찰 | 기준기간, 비교대상, 계절·외부요인 검토 |

±20%는 팀이 선택하는 시험 범위이며 문헌이 정한 보편적 기준이 아니다. 시나리오 중 1위 비율은 **분석 시나리오 안의 순위 안정성**이지 사업 성공확률이 아니다.

후보 권역 3곳만으로 PCA·엔트로피 가중치나 예측모형의 정확도를 검증했다고 주장하지 않는다. 변수 중복·상관관계를 통계적으로 검토하려면 더 충분하고 비교 가능한 관측치가 필요하다. 실증 전후 변화만으로 사업의 인과효과가 입증되는 것도 아니다.

## 7. 개발팀이 바로 정리할 산출물

| 순서 | 산출물 | 완료 조건 |
|---|---|---|
| 1 | 논문–개념–지표 연결표 | 각 지표의 채택 이유와 문헌/자체설계 구분 |
| 2 | 지표 사전과 데이터 확보표 | 원자료·단위·분모·기간·공간·결측 처리 정의 |
| 3 | 지역 검토·AHP 설문지 | 점수 기준을 보여주는 비교 문항과 패널 계획 |
| 4 | 버전별 평가 규칙 | 정규화 기준·가중치·필수조건을 고정 |
| 5 | 3개 권역 사례 평가 | 동일한 기준으로 재현 가능, 자료 부족 공개 |
| 6 | 검증 보고서 | 순위 민감도·현장 불일치·적용 한계 설명 |

화면의 근거 보기에는 **원자료 → 지표값 → 점수 변환 → 가중치 → 기여분 → 해석 → 관련 문헌** 순서로 연결한다. 논문 링크만 달아 놓는 것으로 설명을 끝내지 않는다.

### 발표에 사용할 수 있는 문장

> 동행로컬은 관광 잠재력·지속가능관광·접근성 연구를 바탕으로 평가항목을 구성하고, 공공데이터와 현장정보를 연결해 권역별 여건을 설명합니다. 지역 이해관계자 검토와 AHP 조사로 가중치를 정하고, 자료 부족과 결과의 민감도를 공개하는 평가체계를 구축할 계획입니다.

아직 조사를 시행하지 않았으므로 ‘검증했다’, ‘전문가가 확정했다’, ‘성장확률을 예측한다’고 쓰지 않는다. 조사와 검증을 마친 뒤 수행 내용에 맞게 시제를 수정한다.
