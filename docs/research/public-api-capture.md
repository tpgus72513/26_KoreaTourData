## 재현

Node.js 24와 기존 의존성이 설치된 저장소에서 `.env.local`에 서버 전용 `TOUR_API_SERVICE_KEY`를 설정한 후:

```powershell
node --disable-warning=ExperimentalWarning scripts/capture-tourism.mjs --date=20260820
```

스크립트는 기존 검증된 API 어댑터를 재사용한다. 지역코드 확인 → 전체 페이지 수집 → 응답 건수·중복·기간 확인 → 공개 필드 정규화 → `src/data/tourism-publication.json` 발행 순서다. 일부 API 실패 또는 방문자 자료 부재 시 발행을 중단하고 기존 사본을 유지한다. 오류에는 키·요청 URL·응답 본문을 출력하지 않는다. 저장 전 키가 결과에 포함되지 않았음을 검사한다.

사본은 배포에 포함되는 공개 관광정보로 DB와 키 없이 조회된다. 실시간 호출·자동 갱신을 주장하지 않는다. 변경하려면 다시 수집하고 재배포한다. DB를 사용하는 기존 `/api/sync` 운영 동기화 경로와 별개다.

## 평가·업무 시연과의 경계

- 실제 API 자료 화면에서 권역 점수·사업 우선순위를 계산하지 않는다. 관광시설 수는 체류시간·매출액·접근성의 독립 관측값이 아니다.
- `/evaluation`의 논문 근거 계산은 합성 관측값·임시 가중치로 명시된 모형 시연이다.
- `/data`에서 선택 권역의 근거 상세 시연, 실행과제, 현장검증 화면으로 이동할 수 있다. 이 흐름은 별도의 예시이며 실제 API 관측값에 따른 확정 사업 판단이 아니다.
- 실제 점수 산출에는 별도 현장·소비·체류 자료와 전문가 평가가 필요하다. 업무 변경은 같은 탭의 세션 내에 보관되며 서버 영구 저장은 운영 DB 연계 후 제공한다.
