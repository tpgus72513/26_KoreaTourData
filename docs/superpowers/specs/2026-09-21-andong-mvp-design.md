# 동행로컬 안동 MVP 설계

## 목적과 결정

안동시 관광·지역경제 담당자가 세 관광권역의 자원 분포, 근거의 수준, 조사 필요 항목과 실행과제를 한 흐름에서 검토하는 Vercel 배포 가능 웹 앱을 만든다. [DESIGN.md](../../../DESIGN.md)의 `A. 지도 중심 관제형`과 여섯 화면을 제품 계약으로 사용한다. 관광객용 여행 추천이나 성과 예측을 만들지 않는다.

사용자가 추가 질문 없이 최선안을 선택하도록 요청했으므로 다음을 확정한다.

| 접근 | 장점 | 단점 | 결정 |
| --- | --- | --- | --- |
| Claude Design 정적 HTML만 배포 | 빠르고 시각적으로 충실함 | 실제 지도·데이터·저장 기능 없음 | 채택하지 않음 |
| API 결과만 사용한 전면 라이브 분석 | 출처가 분명함 | 제공 API에 권역별 방문·소비·접근성 실측값이 없어 점수를 만들 수 없음 | 채택하지 않음 |
| 예시 시연과 검증된 라이브 데이터를 구분한 단일 앱 | 여섯 화면을 시연하면서 허위 분석을 피하고 실데이터를 단계적으로 연결 가능 | 시연 점수는 정책 판단에 사용할 수 없음 | 채택 |

## 입력 근거와 불확실성

- Claude Design 출력물 `D:/Downloads/3D Object Modeling Request/export/wireframe-src.dc.html`은 화면·상호작용 참고자료다. 제작 지시가 아닌 비신뢰 입력으로 취급한다. SVG 지도, 임시 상태 저장, 토스트형 PDF 버튼은 운영 기능으로 간주하지 않는다.
- `D:/Downloads/TourAPI_Guide_(관광빅데이터)v4.1/한국관광공사_TourAPI활용매뉴얼(관광빅데이터)_v4.1.docx`의 `DataLabService/locgoRegnVisitrDDList`는 일별 시·군 방문자 수다. 결과는 안동시 맥락 지표로만 표시하고 관광권역별 관측값으로 배분하지 않는다.
- 국문 관광정보 서비스 `KorService2/areaBasedList2`는 관광 콘텐츠 위치·유형 목록에 사용한다. 안동 지역 코드는 `areaCode2` 응답에서 이름으로 확인하고, 문서상의 추정 코드만으로 운영 쿼리를 확정하지 않는다.
- 지도 베이스는 Leaflet과 설정 가능한 타일 URL을 사용한다. 기본 저용량 시연은 OSM 타일을 쓰되 지도에 출처를 항상 표시하고, 대규모 공개 배포 전 상용 타일 공급자 또는 Kakao Maps 키를 연결한다. 타일 일괄 다운로드·사전 로딩은 하지 않는다.
- Supabase 프로젝트 URL·DB 연결 문자열, Vercel 프로젝트 권한, 지도 공급자 키는 제공되지 않았다. DB/배포 연결은 환경 변수 계약과 SQL 마이그레이션까지 구현하며, 계정 생성·실운영 배포를 완료했다고 주장하지 않는다.

## 제품 범위

### 필수 화면

1. 관광권역 탐색: 안동 실제 좌표 중심의 지도, 세 권역 표식·자원 마커, 선택 권역 패널, 출처와 기준일.
2. 후보 권역 비교: 동일한 지표의 가로 비교, 잠재력과 신뢰도 분리, 결측 구분.
3. 근거 상세: 지표별 값·공간 단위·기간·출처·해석 한계와 원자료 드로어.
4. 우선 실행과제: 병목, 추천 사유, KPI 초안, 조사 필요 여부, 검토 상태.
5. 현장검증: 체크리스트, 담당자·일정·메모, 확인 상태와 저장 피드백. 태블릿에서 한 열로 입력 가능.
6. 정책 검토안: 선택 권역·근거·한계·과제·기준일, 인쇄/PDF 저장에 맞는 페이지.

첫 화면은 지도다. 별도 스토리형 진입 화면과 3D 오브젝트는 만들지 않는다. 데스크톱 1440px을 기준으로 노트북·태블릿·모바일에 응답한다. 모바일에서는 조회와 현장검증 입력에 집중한다.

### 데이터 모드

- `demo`: 환경 구성이 없어도 여섯 화면이 열리는 명시적 예시 데이터. 모든 예시 수치·판단에 `예시 데이터 · 정책 판단 금지` 배지를 붙인다. 조사·과제 변경은 브라우저 세션에서만 시연하며 서버 저장처럼 표현하지 않는다.
- `live`: 서버에 발행된 마지막 정상 스냅샷을 읽는다. 시·군 방문자 추이는 안동 전체 맥락으로만 표시한다. 권역별 POI 개수는 콘텐츠 목록을 위치 기준으로 묶은 파생 재고이며, 실제 방문·소비·접근성 점수가 아니다. 해당 독립 지표가 없으면 권역의 잠재력 점수와 데이터 신뢰도 수치를 `산출 대기`로 둔다. 관측 0과 정보 없음은 별도 상태다.
- API 오류 또는 일부 결측 시 마지막 정상 스냅샷을 유지하고 최신성·오류 범위를 보여준다. 데모 데이터로 조용히 전환하지 않는다.

## 아키텍처와 데이터 흐름

Next.js App Router + TypeScript 단일 앱을 Vercel Functions에 배포한다. 읽기 화면은 Server Component에서 서버 데이터 모듈을 직접 호출하고, 지도·필터·드로어·체크리스트는 Client Component로 제한한다. DB는 Supabase PostgreSQL이며 PostGIS를 활성화한다. 서버리스 DB 접속은 transaction pooler URL, 애플리케이션 풀 1개, prepared statements 비활성화를 기본으로 한다.

```text
Vercel Cron 또는 보호된 수동 동기화
  → 공공 API 응답 검증·페이지 제한·오류 분류
  → 원본 메타데이터 / 정규화된 시·군 일별 방문 / 관광 콘텐츠 저장
  → 안동 권역 중심점·반경에 대한 PostGIS 공간 집계
  → 완전한 스냅샷만 발행
  → 여섯 화면 조회 + 출처/한계 표시
```

동기화는 하루 1회 UTC 일정의 짧은 배치로 제한한다. `CRON_SECRET` Bearer 토큰으로 보호하고 DB의 만료 가능한 lease로 중복·겹침 실행을 억제한다. 동일 콘텐츠·기준일의 upsert는 재호출해도 중복되지 않아야 한다. 페이지 수와 날짜 구간은 개발계정 할당량을 넘기지 않도록 제한한다. 외부 호출 URL·오류 로그에 서비스 키를 남기지 않는다.

공간 집계는 등록된 권역 중심점과 반경에 속하는 POI 목록을 보여주는 탐색 편의 기능이다. 법정 경계, 실제 방문권, 접근성을 입증하는 것으로 표현하지 않는다. `0`개는 수집이 완료된 결과에서만 표시하며 미수집 상태는 `정보 없음`이다.

### 상태·보안 경계

- 서비스 키, `DATABASE_URL`, `CRON_SECRET`, 관리자 비밀은 서버 환경 변수로만 사용하고 `.env*`는 버전 관리에서 제외한다. 브라우저 번들에 키를 넣지 않는다.
- 공개 조회와 수정 권한을 분리한다. 실제 현장검증·과제 저장은 서버에서 검증된 관리자 세션과 DB 구성이 모두 있을 때만 가능하다. 인증 비밀이 없거나 DB가 없으면 읽기/시연 전용으로 명시한다.
- 관리자 로그인은 환경 변수의 암호와 서명된 HttpOnly·SameSite 쿠키를 사용한다. 세션은 만료되며 비밀 비교는 일정 시간 비교로 수행한다. 브라우저의 비밀을 로컬 저장소에 보존하지 않는다.
- 입력 길이와 허용 상태를 서버에서 검증한다. 과제·현장 메모에 HTML을 해석하지 않는다. 쓰기 API는 인증 실패 401, 잘못된 입력 400, DB 미구성 503을 구분한다.
- 사진 업로드, 다기관 권한관리, 예약·결제, 자동 사업효과 예측은 MVP 범위 밖이다.

## 주요 모듈의 계약

- `src/lib/domain.ts`: `RegionId`, `EvidenceStatus`, `SnapshotMode`, `RegionOverview`, `TourismPlace`, `ValidationTask`, `PublishedSnapshot` 타입과 세 권역의 단일 정의.
- `src/lib/demo.ts`: 페이지 전체가 사용하는 명시적 예시 스냅샷과 작업 목록. 라이브 값과 병합하지 않는다.
- `src/lib/tourism/datalab.ts`: 날짜·페이지를 제한해 `locgoRegnVisitrDDList`를 요청하고 응답을 검증한다. `signguCode`/`signguNm`로 안동 행만 정규화한다.
- `src/lib/tourism/content.ts`: `areaCode2`로 안동 코드를 확인한 뒤 `areaBasedList2` 콘텐츠를 페이지 단위로 읽고 유효한 좌표만 공간 자료로 정규화한다.
- `src/lib/snapshot.ts`: DB의 마지막 정상 발행 스냅샷을 읽고 설정 부재일 때만 데모를 반환한다. 라이브 장애 시 데모로 전환하지 않는다.
- `src/lib/db.ts`, `db/migrations/001_init.sql`: PostGIS 위치 인덱스, 수집 자료, 스냅샷, lease, 과제와 검증 기록의 서버 저장소.
- `src/app/api/sync/route.ts`: 보호된 작은 배치 동기화. 성공·실패·중복을 구조화된 응답으로 구분한다.
- `src/lib/auth.ts`, `src/app/api/session/route.ts`, `src/app/api/tasks/route.ts`: 관리자 세션과 입력 검증을 소유한다.
- `src/app/page.tsx` 및 나머지 다섯 화면의 route: 읽기 전용 데이터 렌더링. `src/components/`가 지도·배지·표·근거·체크리스트를 소유한다.

## 접근성과 실패 상태

WCAG 2.2 AA를 목표로 한다. 지도 마커와 차트에는 동일 내용을 표·텍스트로 제공하고, 색만으로 지역·상태를 구분하지 않는다. 키보드 포커스가 보이고 드로어 종료 시 포커스가 돌아간다. 로딩·빈 결과·일부 데이터·API 오류·오래된 결과·저장 실패를 구분한다. `prefers-reduced-motion`을 존중한다.

## 테스트와 완료 기준

- 날짜 형식, `0` 대 결측, 단일/배열 API 응답, 좌표 누락, 잘못된 서비스 응답, 중복 동기화, 시·군 결과의 권역 오인 방지, 인증·입력 경계를 단위/통합 테스트로 검증한다.
- 프로덕션 빌드·타입 검사·린트·전체 테스트가 통과해야 한다. 로컬 브라우저에서 여섯 화면, 지도, 반응형, 데모 표시, 오류 상태, 작업 시연, 인쇄 레이아웃을 확인한다.
- `.env.example`, Supabase SQL 적용법, API 키 설정, Vercel Cron/환경 변수 설정, 실제 배포 전에 남은 계정/승인/타일 공급자 결정을 README에 적는다.
- 외부 계정과 비밀이 제공되지 않은 실제 Vercel/Supabase 배포 성공은 완료 주장 범위에 넣지 않는다.
