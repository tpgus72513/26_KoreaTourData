# 논문 기반 평가방법 구현 계획

사용자 요청: 기존 논문 설계안의 점수 계산을 코드에 추가하고 검증 후 GitHub에 push한다. 기존 레포 개선사항도 함께 포함한다.

## 구현 범위

1. 순수 TypeScript 계산 모듈: 고정 기준 정규화, 영역 안/영역 간 가중합, 결측 범위와 확보율, 필수조건 별도 판정.
2. AHP: 1–9/역수 척도, 주고유벡터, CI/CR, 응답 행렬의 기하평균. 잘못된 행렬·불일치 응답을 조용히 채택하지 않는다.
3. 공통 예시 자료: 임의 총점 72/68/61을 제거하고, 출처가 명시된 합성 관측값으로 계산한다. 원도심의 문헌 설명 예시는 65점, 접근성 자료를 비운 사례는 55~75점과 확보율 80%가 되어야 한다.
4. 화면 연결: 비교·근거 상세·보고서에서 같은 계산 결과를 사용한다. 실험실에서 입력값과 AHP 비교를 바꾸고 결과를 확인한다.
5. 민감도: 동등가중치와 각 영역 상대 ±20% 조정 후 재정규화 시나리오를 비교한다. 누락자료가 있으면 해당 비교집단 순위를 보류한다.
6. 문서와 검증: 논문이 제시한 방법과 우리 서비스의 지표·가상 기준을 구별한다. 수치 예제/경계값/화면 회귀/전체 테스트/빌드/브라우저를 확인한다.

## 표시·운영 계약

- 실제 전문가 설문이나 현장 관측을 수행했다고 주장하지 않는다. 동등가중치와 실험실 AHP 입력은 시연이다.
- 합성 자료는 demo에서만 사용한다. 라이브 스냅샷에 실증 입력이 없으면 산출 대기를 유지한다.
- 관측값의 출처·기간·공간·분모가 평가 기준과 맞아야 계산에 쓴다. 없거나 부적합하면 0점으로 대체하거나 남은 가중치를 재배분하지 않는다.
- CR은 판단 일관성 검사다. 확보율은 가중치 기준 자료 확보 정도다. 결측 범위와 민감도 범위는 통계적 신뢰구간이 아니다.
- 필수조건 미충족은 개선 필요, 미확인은 조사 필요로 표시한다. 높은 종합점수로 상쇄하지 않는다.
- 현장과제 완료는 조사의 진행 상태다. 이를 지표값이나 필수조건 충족으로 자동 전환하지 않는다.
- 기존 로컬 작업 브랜치를 원격에 push하며, main 강제 덮어쓰기나 배포는 수행하지 않는다.

## 인수 기준

- 70을 [20,100] 기준으로 변환하면 62.5점.
- 영역점수 [80,60,70,50,65]·각 20%이면 65점.
- 위 사례의 네 번째 영역이 결측이면 총점 null, 범위 55~75점, 확보율 80%.
- 잘못된 가중치/범위/행렬/중복 관측값은 명시적으로 거부.
- 단위·공간·기간·분모가 부적합한 관측은 점수에 기여하지 않음.
- 자료가 완전해도 필수 이용조건이 fail이면 blocked 상태 유지.
- 비교·상세·보고서와 실험실 계산은 같은 엔진 사용.
